# Mellum BF16 versus Q6 research brief

**Follow-up:** The [recovery report and reproduction bundle](mellum-recovery-2026-10-07/report.md)
add independent-runtime controls and a verified clean-Pi/file-search workaround.
Original BF16 failures reject a quantization-only explanation; no universal
large-context or full historical-session fix has been established.

**Date:** 2026-10-07  
**Question:** Did the Q6 conversion introduce the failed session's behavior?  
**Scope:** Review the supplied telemetry diagnosis and compare original BF16 Thinking weights with the existing Q6 conversion in the same MLX runtime. No serving settings, model filenames, or weights were changed.

## Findings

1. **Claim:** The telemetry demonstrates tool-selection and error-recovery failures below 50k context.
   - **Evidence:** The report records six unregistered-agent calls, including repeated attempts after explicit errors, plus a supervisor reply using a run ID instead of the supplied request ID. Recorded parent contexts were 13,459–33,141 tokens, calculated per response as input plus cache-read tokens. The large cumulative token totals in the report are repeated processing, not a single context window. The retained challenge turn ended without a substantive answer.
   - **Source:** [Session diagnosis](/Users/pauleveritt/.superpowers/diagnosing-superpowers/01a1181c-45a0-7676-b435-9990fffc9b8b/report.md) — supplied local report, accessed 2026-10-07; sections 6.3, 6.4, 6.7 and accompanying `metrics.json`.
   - **Assessment:** Fact about the retained telemetry. It does not identify a model, quantization, or harness defect by itself.

2. **Claim:** The earlier direct-MLX comparison did not isolate quantization.
   - **Evidence:** Both direct generation and oMLX generation used the same Q6 weights. The comparison bypassed oMLX but retained quantization and the MLX model implementation.
   - **Source:** [Native-cache serving validation](2026-10-07-mellum-omlx-native-cache.md) — local validation record, accessed 2026-10-07; retrieval-quality findings.
   - **Assessment:** Fact; this is a clarification of the previous evidence's limits.

3. **Claim:** A matched comparison reproduced the 50k retrieval failure without quantization.
   - **Evidence:** Directly loaded the original BF16 safetensors checkpoint, revision `6f239041e7c79166f75f6788dbf7d1971fe1db89`, without writing a converted checkpoint. Compared it with Q6 in MLX-LM 0.32.0 / MLX 0.32.3, using identical prompt-token hashes, native hybrid caches, prefill steps of 512, greedy decoding, and a 4,096-token output allowance. Both exhausted that allowance without closing their thinking block or producing the required answer containing both code constants.
   - **Source:** [Comparison evidence](2026-10-07-mellum-bf16-q6-evidence.json) — local experiment, 2026-10-07; `greedy`, case `50k-code-document`.
   - **Assessment:** Fact. Q6 quantization is not necessary for this failure under MLX.

4. **Claim:** Original BF16 weights can also reproduce the telemetry's skill-as-agent mistake.
   - **Evidence:** Reconstructed the captured context through the first `Unknown agent: brainstorming` result, including nine tool definitions. The resulting prompt was 24,299 tokens. Under greedy decoding, BF16 and Q6 both emitted a valid `read` call for the brainstorming skill. At temperature 1, top-p 0.95, top-k 20, with seeds 42, 43 and 44, BF16 seed 42 emitted `subagent` with `agent: using-superpowers`, which is not a registered agent. BF16's other two runs selected existing skill files. Q6 guessed two nonexistent skill paths and selected an existing pi-subagents skill path in the third run. No generated tools were executed.
   - **Source:** [Comparison evidence](2026-10-07-mellum-bf16-q6-evidence.json) — local experiment, 2026-10-07; `greedy` telemetry case and `sampling`.
   - **Assessment:** Fact about these continuations. This reproduces one failure class with original weights; it is not a replay of the complete multi-turn loop. Three seeds do not establish relative model error rates.

5. **Claim:** The inspected conversion data matches the intended MLX quantization operation.
   - **Evidence:** Original and Q6 configuration JSONs are identical after removing Q6's quantization fields. Tokenizer and chat-template bytes are identical, and all experimental prompt-token hashes match. Independently re-quantized 64 source rows from the embedding, layer-0 query projection, layer-0 router, and layer-0 expert-0 up projection. Stored packed weights, scales, and biases matched the rebuilt values exactly: 6 bits for the ordinary matrices and 8 bits for the router, affine mode, group size 64. The layer-0 query normalization vector is unchanged. Sampled relative weight RMSE is approximately 2.3% for the 6-bit matrices and 1.3% for the router.
   - **Source:** [Comparison evidence](2026-10-07-mellum-bf16-q6-evidence.json) — local experiment, 2026-10-07; `configuration_audit`, `weight_audit`, `exact_quantization_audit`.
   - **Assessment:** Fact about sampled tensors. No packing or configuration error was found in this sample; it is not an exhaustive audit of all tensors or proof that quantization has no quality cost.

## Comparison summary

| Check | Original BF16 in MLX | Existing Q6 in MLX |
| --- | --- | --- |
| Short arithmetic, greedy | Correct `4` | Correct `4` |
| First tool-error continuation, greedy | Valid `read` call | Valid `read` call |
| Tool-error continuation, temperature 1, three seeds | One unregistered-agent call; two existing skill paths | Two nonexistent skill paths; one existing skill path |
| 50k retrieval, greedy, 4,096 output tokens | Failed; output allowance exhausted in thinking | Failed; output allowance exhausted in thinking |

Selecting a valid tool or existing path is a narrow protocol observation. It does
not mean the model correctly answered the human's methodological challenge or
chose an appropriate workflow.

## Open questions and limits

- Original BF16 inference still used MLX's Mellum implementation and weight sanitization. This comparison isolates Q6 quantization but cannot distinguish original-model behavior from a shared MLX implementation issue.
- The captured system sections omit the original bootstrap noted in the diagnosis. Pi records were translated into OpenAI-style messages, retaining recorded reasoning content. This is a controlled continuation of reconstructed input, not an exact reproduction of the historical HTTP request.
- Each generation used fresh native caches and did not use oMLX or its SSD prefix restoration. Those components are not required to produce the observed failure classes, although they could still affect the historical session.
- Original and Q6 models received identical token sequences and decoding settings. Different weights produce different probability distributions; matching seeds does not keep sampled outputs identical.
- The long retrieval prompt contains substantial repetition. These experiments do not measure performance on normal repository tasks or prove that all long-context tasks fail.
- The original checkpoint ran on the 128GB Mac for diagnosis. It is not a replacement suitable for the 16GB serving target.

## Recommendation

The evidence rejects a **Q6-conversion-only explanation**. Confidence is high
that these failure classes can occur with the original weights in MLX, and the
sampled transform data shows the intended quantization. Q6 may still change or
worsen behavior; this small comparison cannot measure that effect reliably.

Before calling it a base Mellum defect, run the original BF16 checkpoint with an
independent implementation on matched prompts. JetBrains documents vLLM serving
with the `qwen3` reasoning parser and `hermes` tool parser in the
[original model card](https://huggingface.co/JetBrains/Mellum2.1-12B-A2.5B-Thinking/blob/6f239041e7c79166f75f6788dbf7d1971fe1db89/README.md), accessed
2026-10-07; serving instructions and evaluation notes. That reference run would
separate original-model/harness behavior from a shared MLX implementation issue.
There is no current evidence that rebuilding the same Q6 files would address it.

## 2026-10-07 independent-runtime follow-up

A subsequent [direct llama.cpp comparison](2026-10-07-mellum-independent-runtime.md)
used a BF16 GGUF generated from the same original Mellum2.1 revision. Prompt
tokens matched exactly. The 50k retrieval failure reproduced under both greedy
decoding and one sampled continuation, and one sampled telemetry continuation
invented a nonexistent skill path. This strengthens the original-model/decoding
explanation and removes the need for a shared MLX defect to explain the greedy
retrieval result. The exact historical unknown-agent loop was not reproduced in
the independent runtime's three sampled continuations.
